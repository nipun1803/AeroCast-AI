# Reproducibility

## Environment

Python 3.12.11 on macOS 27.2, Apple M3 Pro (11 cores, 18 GB), CPU only. The venv is shared with Phase 1 at the repository root. `requirements.txt` pins the Phase 1 packages (`-r ../phase1/requirements.txt`) plus `torch==2.15.0`.

```bash
python3.12 -m venv ../.venv
../.venv/bin/pip install -r requirements.txt
../.venv/bin/pip install -e ../phase1 -e .
../.venv/bin/python -m ipykernel install --sys-prefix --name aerocast   # notebook kernel
```

Place the Kaggle `flights.csv` in `../phase1/data/raw/`. Phase 2 reads it through `aerocast.config.RAW_CSV`.

**Determinism.** Every random generator is seeded: search seed 42, ensemble seeds 42–46. Torch runs on 8 threads with `torch.use_deterministic_algorithms(True)`. Two fits from the same seed give identical weights (`tests/test_train.py::test_same_seed_same_model`).

**Torch and XGBoost in one process.** On macOS the two OpenMP runtimes crash (exit 139) if XGBoost is imported before torch. `import aerocast_dl` loads torch first and raises if XGBoost is already loaded. Every XGBoost fit in Phase 2 runs in a torch-free subprocess (`scripts/xgb_worker.py`).

## Stages

`python -B scripts/run_phase2.py` runs every stage except `final`. A subset can be run with `--stages ...`. Times are from the recorded run on 2026-11-10/11.

| Stage | What it does | Labels read | Time |
|---|---|---|---|
| `data` | network inputs, fitting clock, cold-start coverage | train | < 1 min |
| `sequences` | causal 28-day windows, equality with the Phase 1 history features | train | < 1 min |
| `mlp` | 20-configuration search (seed 42), 5-seed CV of the best | train (CV) | 4 min |
| `gru` | 12-configuration search, 5-seed CV | train (CV) | 28 min |
| `hybrid` | Wide & Deep: 12-configuration search, 5-seed CV | train (CV) | 26 min |
| `emb_xgb` | MLP embeddings → Phase 1 XGBoost, 20 fits in a subprocess | train (CV) | 1 min |
| `ablation` | 16 ablations, 5-seed CV | train (CV) | 39 min |
| `figures` | CV comparison, ablations, learning curves | train (CV) | 3 min |
| `diagnostics` | why the MLP trails LogReg (single seed) | train (CV) | 1 min |
| `final_fit` | refit every family on rows known by 2013-09-01, scores for every row | train | 3 min |
| `calibrate` | Sep→Oct calibrator rule, frozen thresholds, final-model rule | train, Sep–Oct | < 1 min |
| `reschedule` | what-if rule tuned on Sep–Oct | Sep–Oct | 3 min |
| `final` (`--final` only) | the one test evaluation, slices, drift, rescheduling on Nov–Dec | **Nov–Dec** | 2 min |

The `final` stage runs only through `run_phase2.py --final`. It refuses to run while `docs/development_protocol.md` or `docs/leakage_safeguards.md` has uncommitted changes (`aerocast_dl.testlock`). In development it was run once, on 2026-11-11. Every seed is fixed, so rerunning it reproduces that evaluation without choosing anything.

## Full rebuild

`bash scripts/reproduce.sh` runs, in order:

1. the tests;
2. deletes `results/`, `figures/`, the report assets and `data/cache/`;
3. runs every stage, then `--final`;
4. executes notebooks 05–11 in place;
5. exports the report assets and checks every quoted number;
6. builds the PDF with `tectonic` if it is installed.

It takes about 3 hours. **It has not been run end to end in one go.** Every stage it calls was run individually, as recorded above.

## macOS and iCloud

The repository lives in an iCloud-synced folder, where evicted ("dataless") files hang on read. The venv therefore lives outside iCloud (`~/.venvs/aerocast-ai`), and `../.venv` is a symlink to it.

- **Before a long run or a commit:** `find . -flags +dataless` lists evicted files; `brctl download <path>` fetches them.
- **If `import aerocast` fails:** hidden `.pth` files are skipped by Python. Run `chflags nohidden ../.venv/lib/python3.12/site-packages/*.pth`. The scripts and notebooks add `src/` to `sys.path` themselves, so they work either way.
